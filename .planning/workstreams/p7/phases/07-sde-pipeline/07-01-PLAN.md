    src/sde/timestamp.rs（D-10）：

    定义两个公开函数：

    A. pub fn parse_srt_timestamp(input: &str) -> Result<f64, SdeError>
       解析 "HH:MM:SS,mmm" 格式（SRT 标准）为 f64 秒数。
       也支持 "HH:MM:SS.mmm" 格式（点号分隔符）作为兼容。
       支持 "HH:MM:SS" 格式（无毫秒）作为兼容。
       格式无效返回 SdeError::ParseSubtitle。

    B. pub fn find_precise_range(llm_timestamp: &str, segments: &[SubtitleSegment]) -> Option<(f64, f64)>
       将 LLM 输出的时间范围（"HH:MM:SS,mmm-HH:MM:SS,mmm"）与原始字幕段落精确匹配。
       分割 LLM 时间范围为 start/end，解析为秒数。
       查找与 LLM 范围重叠的字幕段落（±1 秒容差，D-29）。
       返回 matched.first() 的 start_secs 和 matched.last() 的 end_secs（如果匹配结果为空则返回 None）。

    包含 #[cfg(test)] mod tests 块：
    - test_parse_srt_valid: "00:00:05,200" -> 5.2
    - test_parse_srt_dot_separator: "00:00:05.200" -> 5.2
    - test_parse_srt_no_millis: "00:01:00" -> 60.0
    - test_parse_srt_invalid_format: "bad" -> 错误
    - test_parse_srt_invalid_range: "99:99:99,999" -> 错误
    - test_find_precise_range_exact_match: 精确匹配返回正确边界
    - test_find_precise_range_with_tolerance: ±1 秒容差匹配
    - test_find_precise_range_no_match: 无匹配返回 None
    - test_find_precise_range_invalid_timestamp: 无效时间戳返回 None

- Module public API surface in mod.rs

| user input → SdeRequest | Untrusted file paths and parameters cross here |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-01 | Tampering | SdeRequest.validate() | mitigate | 校验 subtitle_path 和 video_path 非空（D-04）。路径参数校验在 validate() 中完成。参数范围校验（voice_rate, voice_pitch, 音量值, threads）。参考 DocumentaryRequest.validate() 的校验模式实现。 |
