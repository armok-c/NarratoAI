    **步骤 A — 创建 src/llm/registry.rs**

    实现运行时 Provider 注册中心（D-05），持有 `HashMap<String, Arc<dyn LlmProvider>>`。完全对齐 Python 版 `LLMServiceManager` 的 register/get 模式。

    ```rust
    use std::collections::HashMap;
    use std::sync::Arc;
    use crate::error::LLMError;
    use crate::llm::provider::LlmProvider;

    /// Provider 注册中心
    ///
    /// 运行时 trait object 注册模式（D-05）：HashMap 持有 Arc<dyn LlmProvider>。
    /// 按 provider 名字符串（小写）索引。
    pub struct Registry {
        providers: HashMap<String, Arc<dyn LlmProvider>>,
    }

    impl Registry {
        /// 创建空注册中心
        pub fn new() -> Self {
            Self { providers: HashMap::new() }
        }

        /// 注册 provider，name 自动转为小写（D-02）
        pub fn register(&mut self, name: &str, provider: Arc<dyn LlmProvider>) {
            self.providers.insert(name.to_lowercase(), provider);
        }

        /// 按名称查询 provider。未找到时返回 LLMError::ProviderNotFound（D-14）
        pub fn get(&self, name: &str) -> Result<Arc<dyn LlmProvider>, LLMError> {
            self.providers
                .get(&name.to_lowercase())
                .cloned()
                .ok_or_else(|| LLMError::ProviderNotFound(name.to_string()))
        }

        /// 返回已注册的所有 provider 名称列表
        pub fn list_providers(&self) -> Vec<String> {
            self.providers.keys().cloned().collect()
        }
    }

    impl Default for Registry {
        fn default() -> Self {
            Self::new()
        }
    }
    ```

    文件不包含 `#[cfg(test)]` 模块——集成测试在 `tests/llm_test.rs` 中。

    **步骤 B — 创建 src/llm/image_utils.rs**

    实现图片预处理流水线（D-20），完全对齐 Python 版 `_image_to_base64` 方法。

    具体行为：
    1. 用 `image::open()` 加载图片文件
    2. 调用 `thumbnail(1024, 1024)` 保持宽高比缩放（与 Python `PIL.Image.thumbnail((1024, 1024), LANCZOS)` 行为一致）
    3. 编码为 JPEG quality=85
    4. base64 编码
    5. 格式化为 `data:image/jpeg;base64,...` data URL

    ```rust
    use std::io::Cursor;
    use std::path::Path;
    use crate::error::LLMError;

    /// 将图片文件预处理为 base64 data URL（D-20）
    ///
    /// 流水线：
    /// image::open() → thumbnail(1024,1024) → JPEG quality 85 → base64 encode → data URL
    pub fn image_to_base64_data_url(path: &Path) -> Result<String, LLMError> {
        let img = image::open(path)
            .map_err(|e| LLMError::Configuration(format!("图片加载失败: {}", e)))?;

        // 缩放到 1024px 保持宽高比，对齐 Python 的 PIL.Image.thumbnail((1024, 1024), LANCZOS)
        let thumb = img.thumbnail(1024, 1024);

        // JPEG 编码 quality=85
        let mut buf = Cursor::new(Vec::new());
        thumb.write_to(&mut buf, image::ImageFormat::Jpeg)
            .map_err(|e| LLMError::Configuration(format!("JPEG 编码失败: {}", e)))?;

        // base64 编码
        let b64 = base64::engine::general_purpose::STANDARD
            .encode(buf.get_ref());

        Ok(format!("data:image/jpeg;base64,{}", b64))
    }
    ```

    注意：
    - 错误映射为非 `LLMError::APICall` 而是 `LLMError::Configuration` — 因为图片处理失败不是 API 问题
    - 使用 `image::DynamicImage::thumbnail()` 而非 `resize_exact()` — 前者自动保持宽高比
    - `base64::engine::general_purpose::STANDARD` 是 base64 0.22 的标准 engine

    **构造函数 `new()`（D-16：代理透传）：**
    - 接收参数：api_key(String), model_name(String), base_url(String), max_retries(u32), timeout_secs(u64), proxy_http(Option<String>), proxy_https(Option<String>)
    - 始终构建 `OpenAIConfig::new().with_api_key(&api_key).with_api_base(base_url.trim_end_matches('/'))`
    - 当 proxy_http 或 proxy_https 为 Some 时，构建自定义 reqwest Client（设置 timeout + proxy）
    - 否则使用 `Client::with_config(config)`（async-openai 默认 reqwest Client）
    - 返回 `Result<Self, LLMError>`（proxy 构建失败返回 LLMError::Configuration）

    **impl LlmProvider for OpenAiCompatibleProvider：**

    （a）`generate_text()` — 非流式文本生成
    - 调用 `self.build_text_messages(prompt, system_prompt)` 构建消息列表
    - 判断 `response_format`：若 `Some(Json)` 则设置 `ResponseFormat { type_: "json_object" }`，否则设为 `None`
    - 用 `CreateChatCompletionRequestArgs::default()` 构建请求
    - 若 `response_format == Some(Json)`，调用 `self.generate_text_with_json_fallback(request, prompt).await`
    - 否则直接调用 `self.client.chat().create(request).await.map_err(LLMError::from)`
    - 通过 `Self::extract_text(&response)` 提取响应文本

    （b）`generate_text_stream()` — 流式文本生成（D-09, D-10, D-11, D-12）
    - 构建消息列表（同上，但不设置 response_format）
    - 调用 `self.client.chat().create_stream(request).await.map_err(LLMError::from)?`
    - 用 `stream.map()` 转换每个 chunk：提取 `chunk.choices.first().and_then(|c| c.delta.content.as_deref()).unwrap_or("").to_string()`
    - 流中途错误返回 `Err(LLMError::from(e))`，立即终止（D-10）
    - 返回 `Ok(Box::pin(mapped))`

    （c）`analyze_images()` — 视觉分析（D-03, D-17, D-18, D-20）
    - 遍历 `images: &[PathBuf]`，对每个路径调用 `image_to_base64_data_url()` → `Vec<String>` data URLs
    - 将所有 data URLs 按 `batch_size` 分片（默认 10）
    - 创建 `Arc<Semaphore::new(max_concurrency)>`（默认 1）
    - 循环：对每个批次 clone 所需数据，spawn 一个 tokio 任务
    - 每个 spawned 任务内部 `semaphore.acquire_owned().await` → `self.client.chat().create(build_vision_request).await` → 提取文本
    - 用 `futures::future::join_all` 或逐个 `.await` 收集所有任务结果
    - 按批次索引排序，连接所有结果文本为 `Vec<String>` 返回
    - **注意**：`self.client` 必须 clone 后传入每个 spawned 任务（async-openai Client 是 Arc 包装，clone 廉价）

    **私有辅助方法：**

    （d）`build_text_messages(prompt: &str, system_prompt: Option<&str>) -> Vec<ChatCompletionRequestMessage>`
    - 如果有 system_prompt，插入 `ChatCompletionRequestMessage::System`
    - 插入 `ChatCompletionRequestMessage::User`，其 content 为单个 Text part

    （e）`build_vision_messages(prompt: &str, base64_images: &[String]) -> Vec<ChatCompletionRequestMessage>`
    - 构建 `Vec<ChatCompletionRequestMessageContentPart>`，第一个是 Text（prompt）
    - 后续是 ImageUrl parts（每个 `data:image/jpeg;base64,...` → `ImageUrl { url, detail: None }`）
    - 包裹为 `ChatCompletionRequestMessage::User`

    （f）`extract_text(response: &CreateChatCompletionResponse) -> String`
    - `response.choices.first().and_then(|c| c.message.content.as_deref()).unwrap_or("").to_string()`

    （g）`generate_text_with_json_fallback(request: CreateChatCompletionRequest, original_prompt: &str) -> Result<CreateChatCompletionResponse, LLMError>`（D-19）
    - 调用 `self.client.chat().create(request).await`
    - 匹配成功 → Ok(response)
    - 匹配 `Err(OpenAIError::ApiError(api_err))` 且 `api_err.status_code == Some(400)` 且 `api_err.message` 小写含 "response_format" → 重建请求（无 response_format），在原 prompt 末尾追加 `"\n\n请确保输出严格的JSON格式，不要包含任何其他文字或标记。"`，重试
    - 其他错误 → `Err(LLMError::from(e))`

    **Helper builder 方法参考：**
    ```rust
    fn build_vision_request(&self, b64_images: &[String], prompt: &str) -> Result<CreateChatCompletionRequest, LLMError> {
        let mut content_parts: Vec<ChatCompletionRequestMessageContentPart> = Vec::with_capacity(1 + b64_images.len());
        
        content_parts.push(ChatCompletionRequestMessageContentPart::Text(
            ChatCompletionRequestMessageContentPartText {
                text: prompt.to_string(),
            },
        ));
        
        for b64 in b64_images {
            content_parts.push(ChatCompletionRequestMessageContentPart::ImageUrl(
                ChatCompletionRequestMessageContentPartImageUrl {
                    image_url: ImageUrl {
                        url: b64.clone(),
                        detail: None,
                    },
                },
            ));
        }
        
        let messages = vec![
            ChatCompletionRequestMessage::User(UserMessage {
                content: Some(content_parts),
                ..Default::default()
            }),
        ];
        
        CreateChatCompletionRequestArgs::default()
            .model(&self.model_name)
            .messages(messages)
            .build()
            .map_err(|e| LLMError::Configuration(format!("请求构建失败: {}", e)))
    }
    ```

    注意：
    - async-openai 0.36 的 `CreateChatCompletionRequest` 实现了 Clone——JSON 回退时可以 clone 后修改，无需完全重建

    - `image_to_base64_data_url` 返回的 `Configuration` 错误应在 analyze_images 中外层统一处理：`images.iter().map(|p| image_to_base64_data_url(p).map_err(...)).collect::<Result<Vec<_>, _>>()?`
    - `generate_text` 中 response_format=None 时不设置 CreateChatCompletionRequest 的 response_format 字段（None/skip）
    - Stream 错误映射用 `futures::StreamExt` 的 `.map()`——需要 `use futures::stream::StreamExt;`
    - `#[cfg(test)]` 模块不需要在此文件—单元测试在 `tests/llm_test.rs` 中
