    ```rust
    use std::path::{Path, PathBuf};
    use std::time::Duration;
    use ffmpeg_sidecar::command::FfmpegCommand;
    use ffmpeg_sidecar::event::FfmpegEvent;
    use crate::visual::error::VisualError;

    ```

    实现 `pub async fn extract_frames_fast_path(
        video_path: &Path,
        output_dir: &Path,
        interval_seconds: f64,
        quality: u32,
        cancel: Option<CancellationToken>,
    ) -> Result<usize, VisualError>`

    流程：
    1. 构建 ffmpeg 命令：`FfmpegCommand::new()` → `hide_banner()` → `loglevel("error")` → `input(video_str)` → `video_filter(format!("fps=1/{}", interval_seconds))` → `codec_video("mjpeg")` → `args(["-q:v", &quality.to_string()])` → `start_number(0)` → `overwrite()` → `output(output_dir.join("fastframe_%06d.jpg").to_str().unwrap())`
    2. 使用 `tokio::task::spawn_blocking()` 包装整个流程（D-14: 不阻塞 tokio 运行时）
    3. 在 blocking 闭包内：`cmd.spawn()` → `child.iter()` 遍历 FfmpegEvent
    4. 检查 `cancel.is_cancelled()` 以支持超时取消（复用 Phase 1 CancelToken 模式）
    5. `child.wait()` 等待完成
    6. 调用辅助函数 `rename_fast_path_frames()` 将 `fastframe_XXXXXX.jpg` 重命名为 `keyframe_XXXXXX_HHMMSSmmm.jpg`（D-24 命名格式）
    7. 返回提取的帧数

    实现 `fn rename_fast_path_frames(output_dir: &Path, interval_seconds: f64) -> Result<usize, VisualError>`：

    1. 扫描 output_dir 下的所有 `fastframe_*.jpg` 文件
    2. 对每个文件提取帧序号（从文件名 regex 捕获 `(\d+)`）
    3. 计算该帧的时间戳：`frame_number * interval_seconds` 秒
    4. 格式化为 `HHMMSSmmm`（例如 `000500000` 表示 5 秒）
    5. 重命名为 `keyframe_{frame_number:06d}_{HHMMSSmmm}.jpg`
    6. 返回重命名的帧数量（如果 output_dir 没有 fastframe_ 文件则返回 0）

    添加 `use tokio_util::sync::CancellationToken;` 作为可选的取消令牌参数。默认使用 `CancellationToken::new()`。

    在 `#[cfg(test)] mod tests { ... }` 中添加：
    - `test_rename_fast_path_frames` — 创建临时目录，写入模拟 fastframe_ 文件，验证重命名结果符合 D-24
    - `test_frame_naming_pattern` — 验证命名格式正则匹配 `keyframe_\d{6}_\d{9}\.jpg`
    - `test_fast_path_noop_when_no_frames` — 空目录返回 Ok(0)

    实现 `pub async fn extract_frames(
        video_path: &Path,
        output_dir: &Path,
        interval_seconds: f64,
        quality: Option<u32>,
        progress: Option<ProgressCallback>,
        cancel: Option<CancellationToken>,
    ) -> Result<usize, VisualError>`（D-11/D-12 主入口）：

    1. 从 `interval_seconds` 参数或默认 3.0 获取帧间隔
    2. 从 `quality` 参数或默认 5（`q:v` 值范围 2-31，越小质量越高）获取质量
    3. 如果 `output_dir` 不存在则创建（`std::fs::create_dir_all`）
    4. **快路径**：调用 `extract_frames_fast_path(video_path, output_dir, interval_seconds, quality, cancel.clone()).await`
    5. 如果快路径返回 `Ok(count)` 且 `count > 0`：
       - 上报进度 `(Some(1.0), "帧提取完成")`
       - 返回 `Ok(count)`
    6. **回退路径**（D-12 回退逻辑）：如果快路径返回 0 帧或失败：
       - 清理快路径残留文件（删除 `fastframe_*.jpg`）
       - 尝试逐帧提取（D-10 完整 4 级回退）

    实现 `async fn extract_frames_fallback(
        video_path: &Path,
        output_dir: &Path,
        interval_seconds: f64,
        quality: u32,
        progress: Option<ProgressCallback>,
        cancel: Option<CancellationToken>,
    ) -> Result<usize, VisualError>`（额外加辅助函数以区分）：

    此函数的内部实现（全部在 `spawn_blocking` 内执行）：
    - 使用 FFprobe 获取视频时长（`ffprobe -v error -show_entries format=duration -of csv=p=0`）
    - 计算总帧数：`duration / interval_seconds`
    - 对每个帧序号，调用 `extract_single_frame()` 按时间戳提取
    - 上报进度：`(Some(frame_idx as f64 / total_frames), "正在提取关键帧")`

    实现 `fn extract_single_frame(
        video_path: &str,
        output_path: &Path,
        timestamp_secs: f64,
        quality: u32,
    ) -> Result<(), VisualError>`：

    按 4 级回退尝试（D-10，对齐 Python `_extract_single_frame_optimized()`）：

    **Level 1 — 硬件加速 JPEG** `output_path` 使用 `.jpg` 扩展名：
    - 添加 hwaccel 参数（`-hwaccel cuda` 或 `-hwaccel auto` 等，从 config 或硬编码检测逻辑获取）
    - `ffmpeg -ss {timestamp} -i {video} -vframes 1 -q:v {quality} -pix_fmt yuv420p -y {output_jpg}`
    - 如果成功（输出文件存在且 > 0 字节），返回 Ok(())

    **Level 2 — 软件解码 JPEG：**
    - 无 hwaccel 参数
    - `ffmpeg -ss {timestamp} -i {video} -vframes 1 -q:v {quality} -pix_fmt yuv420p -avoid_negative_ts make_zero -y {output_jpg}`
    - 如果成功，返回 Ok(())

    **Level 3 — PNG 格式（然后转 JPEG）：**
    - `ffmpeg -ss {timestamp} -i {video} -vframes 1 -pix_fmt yuv420p -f image2 -y {output_png}`
    - 然后使用 image crate 将 PNG 读取并编码为 JPEG quality 85
    - 保存到最终路径

    **Level 4 — BMP/MJPEG 终极兼容：**
    - `ffmpeg -ss {timestamp} -i {video} -vframes 1 -f image2 -pix_fmt rgb24 -y {output_bmp}`
    - 用 image crate 读取 BMP 编码为 JPEG
    - 如果仍失败，返回 `VisualError::FrameExtraction`

    所有 FFmpeg 调用通过 `std::process::Command` 执行，在 `spawn_blocking` 闭包内。

    在回退函数中，如果某帧在全部 4 级回退后仍失败，记录 `tracing::warn!("帧提取失败 {timestamp}: {err}")`，继续下一帧（D-14: 收集错误继续执行）。
