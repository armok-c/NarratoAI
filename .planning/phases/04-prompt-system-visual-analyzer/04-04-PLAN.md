    实现 `pub fn parse_and_retry(json_text: &str, max_attempts: usize) -> Result<FrameObservation, VisualError>`（对齐 AI-SPEC 4b 节）：

    - 循环 `attempt in 1..=max_attempts`
    - 每次迭代先防御性清理：
      ```rust
      let cleaned = json_text
          .trim()
          .strip_prefix("```json")
          .or_else(|| json_text.trim().strip_prefix("```"))
          .map(|s| s.trim_end_matches("```").trim())
          .unwrap_or(json_text.trim());
      ```
    - 尝试 `serde_json::from_str::<FrameObservation>(cleaned)`
    - 如果成功，返回 Ok(obs)
    - 如果失败且 attempt < max_attempts，记录 `warn!` 后重试
    - 如果所有尝试均失败，返回 `Err(VisualError::Analysis(format!("JSON 解析失败 ({} 次尝试): {}", max_attempts, last_error)))`

    实现 `fn collect_frame_paths(output_dir: &Path) -> Result<Vec<PathBuf>, VisualError>`（D-24 对齐帧命名模式）：

    - 读取 `output_dir` 目录
    - 过滤匹配 `keyframe_*.jpg` 模式的文件
    - 按文件名排序（字典序，帧序号自然排序）
    - 如果目录下没有匹配文件，返回 `Err(VisualError::FrameExtraction("没有匹配 keyframe_*.jpg 的文件".into()))`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM API 返回 JSON → serde 反序列化 | 第三方 LLM 返回的 JSON 可能偏离预定义 schema |
| 帧文件 → LLM API (HTTPS) | 视频帧图片通过外部 HTTP API 发送给第三方 LLM |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | analyzer.rs — LLM 返回 JSON 包含未知/恶意字段 | mitigate | `FrameObservation` 使用 `#[serde(deny_unknown_fields)]` 拒绝未知字段；`parse_and_retry()` 最多重试 2 次后返回明确错误 |
| T-04-07 | Information Disclosure | analyzer.rs — 帧图片含可识别信息通过 HTTPS 发送 | accept | LLM API 调用通过用户配置的 API endpoint（HTTPS 加密传输）；帧数据仅用于单次分析，不持久化到 LLM 训练集（取决于 provider 数据政策） |
</threat_model>
