修正所有 6 个配置 Pinia store 的 dirty 标志跟踪系统

Purpose: 当前所有配置面板使用 v-model 直接绑定 store refs（如 `v-model="visionConfig.provider"`），绕过所有 mutator 方法（如 `updateVisionConfig()`），导致 `dirty` 永远为 false。结果是保存按钮始终禁用、抽屉关闭不暂存、"未保存的更改"从不显示。

    Why `flush: 'sync'`:
    - Vue 3 watch 默认使用 `flush: 'pre'`（批处理，异步触发）。在 loadConfig() 的同步执行中，watch 回调会在 dirty.value = false 之后才触发，导致加载完后 dirty 错误地变为 true。
    - `flush: 'sync'` 确保 watch 回调在源值变更的同一同步 tick 内立即执行。loadConfig 赋值 → dirty=true（同步）→ dirty=false（下一行重置）→ 最终 dirty=false 正确。
    - 用户编辑（v-model）场景下同样立即生效：赋值 → watch 同步触发 → dirty=true。

    **Important:** Do NOT remove existing `dirty.value = true` from mutator methods (setEnabled, setFolder, updateVisionConfig, etc.). Redundant dirty=true is idempotent and harmless. The mutators still serve their semantic purpose when called programmatically.

    **Important:** Do NOT modify the watch pattern inside `restoreDraft()` in useConfig.ts. The existing code at lines 131-136 already sets `llm.dirty = true, tts.dirty = true, ...` directly after restoring draft values. The watch is not needed there since restoreDraft explicitly sets dirty.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pinia store watch → store.dirty | Reactive dependency — watch callback must not throw to avoid breaking the reactivity system |
| store.dirty → settingsSave button | UI computed property — race condition possible if dirty is mutated during save operation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-06-01 | Tampering | store watch callback | mitigate | Set `dirty.value = true` inside a simple arrow function that cannot throw. No API calls, no async operations inside the watch callback. |
| T-16-06-02 | Denial of Service | flush: 'sync' | accept | `flush: 'sync'` causes watch to fire on every intermediate mutation. For config stores with <10 primitive fields, the overhead is negligible. If performance issues arise, switch to `flush: 'post'` and restructure loadConfig to clear dirty in a nextTick. |
| T-16-06-03 | Information Disclosure | N/A | accept | This plan does not touch credential handling. All credential handling is inherited from existing code paths (useConfig collectChangedFields, tauriInvoke). |
</threat_model>
