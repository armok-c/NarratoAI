# Plan 03: Frame Analysis → Script Generation Pre-processor

<objective>
Implement `generate_documentary_script()` — the independent pre-processing function that extracts keyframes from a video, analyzes them via vision LLM, then generates a narration script via text LLM. Users call this first, edit the result, then feed it into the pipeline.
</objective>

<tasks>

<task id="06-03-01" type="execute">
<read_first>
- src/documentary/error.rs — PipelineError
- src/documentary/types.rs — DocumentaryRequest, ProgressStep
- src/visual/frame_extractor.rs — extract_frames (FFmpeg keyframe extraction with 4-level fallback)
- src/visual/analyzer.rs — batch frame analysis with vision LLM
- src/llm/provider.rs — LlmProvider trait (generate_text method)
- src/prompt/manager.rs — PromptManager::get_prompt / render
- src/config/types.rs — AppConfig (vision/text model settings, frame extraction config)
- app/services/documentary/frame_analysis_service.py — Python reference for full analyze_video + generate_documentary_script flow
- app/services/generate_narration_script.py — Python reference for LLM narration generation + JSON repair
</read_first>
<action>
1. Create `src/documentary/script_gen.rs`:

2. Define `ScriptGenRequest` struct:
   - `video_path: PathBuf` — input video
   - `video_theme: Option<String>` — optional theme hint
   - `custom_prompt: Option<String>` — additional analysis instructions
   - `frame_interval: Option<f64>` — seconds between keyframes (default from config)
   - `vision_batch_size: Option<usize>` — frames per LLM batch (default from config)
   - `vision_model: Option<String>` — override vision model
   - `text_model: Option<String>` — override text model
   - `max_concurrency: Option<usize>` — parallel LLM batches (default from config)
   - `progress: Option<Box<dyn Fn(f32, &str) + Send + Sync>>`

3. Define `FrameAnalysisResult` struct:
   - `analysis_json_path: PathBuf` — saved analysis artifact
   - `keyframe_files: Vec<PathBuf>` — extracted keyframe paths
   - `batches: Vec<FrameBatchResult>` — parsed batch results (reuse visual::types if available, or define locally)

4. Define `FrameBatchResult` struct (if not already in visual::types):
   - `batch_index: usize`
   - `time_range: String`
   - `frame_observations: Vec<FrameObservation>`
   - `overall_activity_summary: String`
   - `status: String` — "success" or "failed"

5. Define `FrameObservation`:
   - `timestamp: String`
   - `observation: String`
   - `frame_path: Option<PathBuf>`

6. Implement `analyze_video(request: &ScriptGenRequest, config: &AppConfig) -> Result<FrameAnalysisResult, PipelineError>`:
   - Extract keyframes: call `visual::frame_extractor::extract_frames(video_path, output_dir, interval)` with caching (check if keyframes already exist in cache dir)
   - Chunk keyframes into batches of `vision_batch_size`
   - For each batch: build analysis prompt, call `visual::analyzer` with vision LLM
   - Parse each batch response as JSON: extract `frame_observations` and `overall_activity_summary`
   - Calculate time ranges from keyframe filenames (format: `keyframe_NNNNNN_HHMMSSmmm.jpg`)
   - Save analysis artifact to JSON file
   - Progress updates: 10% "提取关键帧", 30% "初始化分析器", 40-65% "分析批次 (N/M)", 75% "逐帧分析完成"

7. Implement `generate_narration(analysis_markdown: &str, config: &AppConfig, text_model: Option<&str>) -> Result<Vec<ScriptClip>, PipelineError>`:
   - Get narration_generation prompt template from PromptManager
   - Render template with `video_frame_description` = analysis_markdown
   - Call text LLM (generate_text or chat completion) with the rendered prompt
   - Parse LLM response as JSON:
     - Try direct JSON parse
     - If fails: strip ```json fences, try again
     - If fails: find first `{` to last `}`, try again
     - If fails: apply JSON repair (replace `{{` → `{`, fix trailing commas, fix single quotes)
   - Extract `items` array from parsed JSON
   - Each item should have: `picture`, `narration`, `timestamp`, `OST`
   - Convert to `Vec<ScriptClip>` using serde deserialization
   - Default OST=2 for all generated items (matching Python behavior)

8. Implement `convert_analysis_to_markdown(analysis: &FrameAnalysisResult) -> String`:
   - Sort batches by time range
   - For each batch: "## 片段 {N}\n- 时间范围：{time_range}\n- 片段描述：{summary}\n- 详细描述：\n  - {timestamp}: {observation}\n..."
   - Return complete markdown string

9. Implement `pub async fn generate_documentary_script(request: ScriptGenRequest, config: &AppConfig) -> Result<Vec<ScriptClip>, PipelineError>`:
   - Call `analyze_video()` → get FrameAnalysisResult
   - Call `convert_analysis_to_markdown()` → markdown string
   - Call `generate_narration()` → Vec<ScriptClip>
   - If video_theme or custom_prompt provided, append as context to markdown
   - Progress: 80% "生成解说文案", 100% "脚本生成完成"
   - Return script (user can then save/edit and pass to run_documentary)

10. Update `src/documentary/mod.rs`: export `script_gen::generate_documentary_script`, `ScriptGenRequest`.
</action>
