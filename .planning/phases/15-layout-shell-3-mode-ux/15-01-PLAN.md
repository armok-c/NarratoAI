  <action>
    在 Cargo.toml 的 [dependencies] 段新增 `sysinfo = "0.33"`（latest stable 兼容 Rust edition 2021）。创建 `src-tauri/src/commands/system.rs`：定义 `SystemStats` 结构体（Serialize，字段 cpu_percent: f64, ram_percent: f64），定义 `SystemState` 包装结构体（pub struct SystemState(pub Mutex&lt;System&gt;)），实现 `get_system_stats` Tauri 命令 — 签名 `async fn get_system_stats(state: State<'_, SystemState>) -> Result&lt;SystemStats, String&gt;`，内部：lock mutex → refresh_all() → 读取 global_cpu_info().cpu_usage() → 计算 used_memory/total_memory*100 → 返回 SystemStats。在 `src-tauri/src/commands/mod.rs` 新增 `pub mod system;` 和 `pub use system::*;`，在 `register_all_commands!()` 宏中新增 `crate::commands::system::get_system_stats,`。在 `src-tauri/src/lib.rs` 的 setup 闭包中，在 Ok(()) 之前新增 `app.manage(SystemState(Mutex::new(System::new_all())));`，在文件顶部新增 `use crate::commands::system::SystemState;` 和 `use sysinfo::System;` 和 `use std::sync::Mutex;`（Mutex 如果尚未 import）。

    关键约束：
    - 使用 `std::sync::Mutex`（而非 tokio::sync::Mutex），因为 sysinfo 不需要 async，且每次调用只锁定几毫秒
    - 不要在 `get_system_stats` 内创建新的 System 实例 — 必须复用 Tauri State 中的实例（CPU 百分比依赖 delta 计算）
    - 错误处理：lock 失败返回 String 错误，total_memory 为 0 时返回 0.0
    - cpu_percent 和 ram_percent 直接作为 f64 返回，不四舍五入
  </action>
